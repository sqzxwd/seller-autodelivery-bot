Асинхронный отказоустойчивый каркас бота для продавцов цифровых товаров (ключи активации, подписки, лицензии, аккаунты). Обеспечивает автоматическую и моментальную выдачу товаров покупателям 24/7.

---

## 📌 Решаемая проблема

При ручной обработке заказов на маркетплейсах продавец сталкивается с ключевыми рисками:
- **Задержки выдачи**: покупатели ждут активации часами, что снижает конверсию и рейтинг магазина.
- **Человеческий фактор и повторная выдача**: случайная отправка одного и того же ключа двум покупателям приводит к диспутам и блокировкам.
- **Отсутствие ночного дежурства**: продажи в нерабочее время простаивают без моментальной доставки.

**AutoDelivery Seller Bot** решает эти проблемы:
1. **Атомарная выдача**: ключ списывается на уровне СУБД в монопольной транзакции — дубликаты физически исключены.
2. **24/7 автоматизация**: фоновый цикл опрашивает API маркетплейса, списывает ключ и моментально отправляет его в чат сделки.
3. **Мгновенные Telegram Push-уведомления**: продавец получает отчет по каждому выданному заказу (с маскированием ключа) и алерт, если складские остатки опустились ниже критических 3 штук.

## 🚀 Быстрый старт за 3 шага

### Шаг 1. Клонирование и настройка окружения
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### Шаг 2. Конфигурация переменных
Скопируйте шаблон и укажите свои параметры (при необходимости работы без Telegram оставьте токен пустым):
```bash
cp .env.example .env
```
Пример содержимого `.env`:
```env
MARKETPLACE_API_KEY=your_marketplace_api_token
MARKETPLACE_API_URL=https://api.marketplace.local/v1
DATABASE_PATH=keys.db
POLL_INTERVAL_SECONDS=3.0
TELEGRAM_BOT_TOKEN=123456789:ABCdefGhIJKlmNoPQRstuVWXyz
TELEGRAM_CHAT_ID=987654321
```

### Шаг 3. Запуск демонстрационного режима
```bash
python main.py run --demo
```

## 🏛 Архитектура и надежность

```
┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐
│ Marketplace API │ <───> │  Worker (Async) │ <───> │ Telegram API    │
│  (HTTPX Client) │       │   (main.py)     │       │ (notifier.py)   │
└─────────────────┘       └────────┬────────┘       └─────────────────┘
                                   │
                                   ▼
                         ┌───────────────────┐
                         │   KeyStorage      │
                         │ (SQLite WAL Mode) │
                         └───────────────────┘
```

1. **Гарантия атомарности (Zero Double-Spend)**:
   - База данных SQLite функционирует в режиме `PRAGMA journal_mode=WAL` и `busy_timeout=5000`.
   - Резервирование ключа выполняется атомарным выражением в монопольной транзакции:
     ```sql
     BEGIN IMMEDIATE;
     UPDATE keys
     SET is_used = 1, order_id = ?, used_at = datetime('now')
     WHERE id = (
         SELECT id FROM keys
         WHERE is_used = 0 AND category = ?
         ORDER BY id ASC LIMIT 1
     )
     RETURNING item_key;
     COMMIT;
     ```
   - Даже при параллельных конкурентных воркерах один и тот же ключ никогда не выдается дважды.
2. **Graceful Shutdown**:
   - Перехват системных сигналов `SIGINT` (Ctrl+C) и `SIGTERM` через `asyncio.Event`.
   - Текущая транзакция и сетевой запрос завершаются штатно до остановки процесса; базы данных и HTTP-сессии закрываются без утечек ресурсов.
3. **Безопасность данных**:
   - Токены и секреты строго изолированы в `.env` (добавлен в `.gitignore`).
   - Ключи в логах и Telegram-уведомлениях маскируются алгоритмом `mask_key` (`STEAM-****-9999`).
4. **Стандарты Python 3.14+**:
   - Нативная строгая типизация (`list[]`, `dict[]`, `X | Y`, `typing.Annotated`).
   - Паттерн-матчинг `match/case` для кодов ответа и статусов выдачи.
