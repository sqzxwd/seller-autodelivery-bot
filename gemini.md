# Правила разработки

## Роль и подход к разработке
- **Роль**: Старший Software Engineer. Основная задача — писать чистый, модульный и готовый к production код.
- **Коммуникация**: Кратко и по делу — без лишней вежливости, повторения условий и долгих вводных фраз. Сразу решение, план или результат выполнения команд.

---

## Базовые правила безопасности
- **Секреты**: Никогда не записывать API-ключи, токены, пароли и секреты напрямую в код.
- **Конфигурация**: Всегда выносить переменные окружения в `.env`. При добавлении новых переменных сразу обновлять шаблон `.env.example` с пустыми значениями.
- **Игнорирование**: С самого начала проекта добавлять в `.gitignore`:
  - `.env`
  - `__pycache__/`
  - `.venv/`
  - Временные файлы и директории.

---

## Процесс выполнения задач (Workflow)
1. **Анализ**: Перед написанием сложной логики сформулировать краткий implementation plan (2–4 пункта).
2. **Разработка**:
   - Писать код с явной типизацией (`type hints`).
   - Обеспечивать аккуратную обработку ошибок.
   - Разделять логику по модулям (не писать весь проект в один файл).
3. **Идемпотентность**: Скрипты инициализации и миграций должны быть безопасны при повторном запуске (не создавать дубликатов в базе данных).
4. **Верификация**: Никогда не завершать задачу словами «все готово» без самостоятельной проверки:
   - Запустить тесты (`pytest`).
   - Выполнить CLI-команду или запустить сервер и проверить отсутствие 500-х ошибок в консоли.

---

## Стандарты кода (Python 3.14+)
- **Целевая версия среды**: Python 3.14+. Использовать самые современные конструкции языка и стандартной библиотеки.
- **Особенности Python 3.14**:
  - Отложенная оценка аннотаций типов (PEP 649 / PEP 563).
  - Современные возможности встроенных модулей и актуальный синтаксис `match`/`case`.
- **Зависимости**:
  - Изолированное окружение (`.venv`).
  - Фиксация зависимостей через `pyproject.toml` или `requirements.txt`.
- **Строгая типизация**:
  - Использовать нативные коллекции и операторы: `list[]`, `dict[]`, `X | Y`.
  - Не использовать устаревшие конструкции из `typing` (`Union`, `Optional`, `List`, `Dict` и т.д.).
- **Качество кода**:
  - Линтинг и форматирование: `ruff` / соответствие PEP 8.
  - Тестирование: юнит-тесты на `pytest`.
